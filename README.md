# Лаборатория сопоставления слов с шаблоном

Локальное приложение на React, TypeScript и Electron. Задания, результаты, тема и правила штрафов сохраняются в `localStorage` текущей установки. Ученики и преподаватель используют одно локальное хранилище; синхронизации между компьютерами нет.

## Преподаватель

Вход: логин `Преподаватель` (сохраняется существующая локальная проверка входа).

- Задание содержит название и описание. Алфавиты и шаблон задаёт ученик.
- Результаты доступны из задания и общей вкладки; фильтры по группе и заданию работают совместно.
- В результате видны условие, ученик, группа, дата, полный шаблон, входное слово, алфавиты и определения множеств, переходы, результат сопоставления, ошибки ввода и отдельные штрафы за них.
- Во вкладке результатов раздел «Ошибки и штрафы» позволяет задать отдельный штраф от 0 до 100 для каждой категории. По умолчанию каждая ошибка стоит 5 баллов.
- Штрафы применяются к новым попыткам. Сохранённые результаты содержат снимок штрафов и не пересчитываются при изменении настроек.
- Смена темы и выход доступны в верхней панели.

## Ввод алфавитов учеником

1. Укажите ФИО и группу, откройте задание.
2. Введите **алфавит нетерминалов**, например `BD` или `{BD}`. Нетерминалы — заглавные английские буквы. `{}` означает отсутствие пользовательских нетерминалов.
3. Введите **алфавит терминалов**, например `{а-яА-ЯёЁ0-9_␣}`. Набор задаётся самостоятельно; заготовок нет. Строчные английские буквы в терминальных множествах недопустимы. Заглавная английская буква рассматривается как ссылка на объявленный нетерминал; необъявленная буква — ошибка ввода.
4. Добавьте описания используемых нетерминалов: `B = {а-яА-ЯёЁ}`, `D = {0-9}`. Описание может ссылаться на другое объявленное множество, например `B = {D}`. Ссылки раскрываются при сопоставлении; циклы недопустимы.
5. Введите шаблон из терминалов и объявленных нетерминалов, затем входное слово. Каждый символ входного слова должен принадлежать заданному алфавиту терминалов. При вводе символа вне алфавита ошибочное слово остаётся видимым, показывается «Ошибка» и форма блокируется на **1000 мс**. Затем поле слова очищается и ввод возобновляется. Каждый символ вне алфавита записывается как ошибка текущей попытки; действия во время паузы не добавляют повторных ошибок.
6. «Далее» проверяет алфавиты, определения и принадлежность символов входного слова алфавиту терминалов. Если остались ошибки, форма остаётся открытой. Сопоставление начинается только с корректными определениями и непустым шаблоном.

`L` встроен и принимает любой один символ, включая буквы, цифры, пробел, пунктуацию и Unicode. Его не нужно объявлять; переопределять его множество нельзя. Указание `L` в алфавите нетерминалов допускается.

Множества поддерживают слитную запись и диапазоны: `{а-яБ-Я_}`. Диапазоны включают обе границы; регистр учитывается, `ё` и `Ё` задаются отдельно. `_` — буквальное подчёркивание; обычный пробел (в том числе в конце слитной записи) и `␣` добавляют пробел в множество. Для буквальных разделителей и скобок используйте экранирование: `\,`, `\;`, `\{`, `\}`. Запятая и точка с запятой остаются разделителями; пробел считается терминалом, а не разделителем.

Пример адреса:

- Алфавит нетерминалов: `BD`.
- Алфавит терминалов: `{а-яА-ЯёЁ0-9_.\,␣}`.
- Определения: `B = {а-яА-ЯёЁ}`, `D = {0-9}`.
- Шаблон: `ул. BBBB, д. DD, кв. DD`.
- Входное слово: `ул. Мира, д. 12, кв. 34`.

## Ошибки ввода и баллы

При вводе необъявленного нетерминала или недопустимого обозначения редактор замораживается на **1000 мс**. Во время паузы показывается «Ошибка»; после паузы удаляется последний ошибочный фрагмент, а ранее введённые значения сохраняются. Ошибка записывается один раз для этого события, до удаления фрагмента. Подробное сообщение сохраняется только для преподавателя. Пока редактор заморожен, шаблон, слово и кнопка «Далее» тоже недоступны. При уходе с экрана отложенная очистка отменяется.

Завершённые описания дополнительно проверяются при потере фокуса; незавершённый глобальный алфавит сам по себе не вызывает очистку корректного описания. «Далее» проверяет оставшиеся ошибки перед загрузкой стека и при нарушениях показывает только «Ошибка», оставляя пользователя на форме. Для неиспользуемых объявленных нетерминалов описания не обязательны; описания требуются для букв в шаблоне и ссылок из используемых множеств. Исправление данных не удаляет уже зарегистрированные ошибки текущей попытки.

Категории штрафов:

| Категория | Ошибка |
| --- | --- |
| `invalid_nonterminal` | Недопустимое обозначение нетерминала |
| `invalid_terminal` | Недопустимые английские буквы в терминалах или диапазоне |
| `unknown_nonterminal` | Ссылка на нетерминал, которого нет в алфавите |
| `duplicate_nonterminal` | Повторное объявление |
| `reserved_nonterminal` | Переопределение встроенного `L` |
| `invalid_set` | Неверные скобки, экранирование, пустое множество или обратный диапазон |
| `cyclic_reference` | Цикл между определениями |
| `outside_alphabet` | Символы вне заданного алфавита |
| `empty_field` | Не заполнен алфавит, обозначение или описание множества |

Каждое зафиксированное нарушение сохраняет категорию, поле и сообщение. Правила преподавателя фиксируются в начале попытки и применяются сразу при регистрации ошибок. Баллы равны `max(0, 100 − сумма штрафов)`. **50 баллов и больше — «Справился», меньше 50 — «Не справился».**

История ошибок и баллы видны преподавателю. После завершения ученик видит «Вы справились с работой» или «Вы не справились с работой» и итоговую оценку «Ваш балл: 95 / 100», без журнала ошибок и списка штрафов. Если балл падает ниже 50 ещё при вводе, форма закрывается, появляется окно «Вы не справились с работой» с итоговым баллом, попытка сохраняется и продолжать её нельзя. Балл показывается и при необходимости повторить сохранение результата. Преподаватель получает текущие данные и пометку «Сопоставление не выполнялось». «Вернуться к редактированию» сохраняет значения полей для новой попытки с отдельной историей; предыдущий результат остаётся у преподавателя. Если запись результата не удалась, сначала нужно повторить сохранение.

## Сопоставление

На этом этапе система только сравнивает слово с шаблоном. Несовпадение символов, короткое или длинное слово дают результат «Не соответствует шаблону» и **не добавляют ошибок ввода или штрафов**. История подготовки не меняет результат сопоставления. Совпадение показывается отдельно от оценки за ввод.

Шаблон загружается справа налево в магазин над дном `Z0`. После загрузки в журнал добавляются «магазин заполнен» и переход в `q2`. Дальнейшие такты сравнивают пары символов и извлекают вершину стека. Для такта нажмите пробел; фокус в поле ввода/кнопке и удержание клавиши не запускают лишних шагов.

Над магазином находятся две выровненные строки — «Входное слово» и «Шаблон», без добавления epsilon. После загрузки указатели показывают текущую пару. Нетерминал проверяет принадлежность символа раскрытому множеству, `L` принимает любой символ, терминал сопоставляется буквально.

Журнал содержит триады `(состояние, входной символ, вершина магазина) → (следующее состояние, следующий входной символ, следующая вершина)`. `ε` обозначает отсутствие символа в переходе; введённое подчёркивание остаётся буквальным символом. `qf` — совпадение, `qERR` — несовпадение. При коротком слове переход сохраняет непроверенный символ магазина, например `(q3, ε, б) → (qERR, ε, б)`. Причина несовпадения сохраняется отдельно от штрафуемых ошибок.

## API и старые данные

- `Task` содержит `id`, `title`, `description`; старые поля грамматики задания игнорируются.
- `TaskController.getTasks(storage?, initialTasks?)` при отсутствии ключа `tasks` один раз сохраняет задания из `src/data/default-tasks.json`. Существующее хранилище, в том числе пустой список после удаления всех заданий, не заменяется. `initialTasks` позволяет изолированно проверять начальное заполнение. `TaskController.exportTasks(download, storage?)` сохраняет JSON через интерфейс `FileDownloadPort`; экспорт содержит только `id`, `title`, `description`.
- `GrammarController.createGrammar(variables, template, alphabet?)` копирует грамматику. `alphabet` содержит введённые строки `terminals` и `nonterminals`. Старые грамматики без `alphabet` продолжают поддерживаться.
- `validateDraft(grammar, field)` проверяет недопустимые символы при редактировании. `validateAlphabet(grammar)` возвращает структурированные `InputError` и проверяет определения, ссылки и принадлежность алфавиту. `validateAll` и `validate` возвращают текстовые сообщения. `validateTerminalSet(values)` — базовая проверка множества без контекста ссылок; для объявленных ссылок применяется `validateAlphabet`.
- `GrammarController.validateInputWord(word, grammar)` проверяет каждый символ слова по `grammar.alphabet.terminals`, используя общий разбор множеств с диапазонами и ссылками на нетерминалы. Для каждого символа вне алфавита возвращается ошибка `outside_alphabet` с полем `input-word`. Отдельной проверки английских букв в слове нет: допустимость самого алфавита проверяется существующим валидатором. Старые грамматики без явного алфавита сохраняют прежнее поведение.
- `PreparationController(policy?)` фиксирует штрафы для попытки; `getGrade()`, `hasFailed()` и `getPolicy()` возвращают текущую оценку, статус остановки и копию правил. `record(errors)` копирует историю ввода до остановки; `getInputErrors()` возвращает независимый снимок. `submit(grammar, word)` блокирует неправильные алфавиты, а после исправления возвращает симуляцию и отдельную историю `inputErrors`. Пустой шаблон блокирует запуск без штрафа. Символы слова вне алфавита терминалов блокируют запуск и учитываются как ошибки ввода; совпадение слова с шаблоном здесь не оценивается.
- `InputGuardController` использует адаптер `TimerPort`; `reject(errors, actions)` записывает ошибки и выполняет заморозку/очистку, `dispose()` отменяет ожидающую очистку. `removeLastWord(value, accepts?)` удаляет последнее ошибочное слово или член слитного множества, сохраняя предыдущие слова, диапазоны и скобки.
- `StudentTaskView` использует тот же `InputGuardController` для задержанной очистки входного слова; необязательный `inputTimer: TimerPort` позволяет проверить длительность паузы без настоящего ожидания. `GrammarEditor` принимает `disabled` для блокировки алфавитов и определений на время ошибки в слове. При уходе с экрана ожидающий таймер отменяется.
- `SimulationController.start(word)`, `loadNext()`, `tick()` выполняют загрузку и сопоставление. `getState()` возвращает независимый снимок. `errors` остаётся пустым; `errorMessage` описывает причину несовпадения, которая не является штрафуемой ошибкой.
- `ScoringController` предоставляет категории, правила по умолчанию, чтение/сохранение правил через `StoragePort` и `grade(inputErrors, policy?)`. Правила хранятся в `automata.scoring`.
- `ResultController.createResult(submission)` принимает отдельно `inputErrors` и необязательный `scoringPolicy`. `createInputFailure(submission)` сохраняет попытку, остановленную по баллам до сравнения (`comparisonPerformed: false`), без вымышленных переходов. Обычный результат сохраняет исправленную грамматику, исходную историю, отдельные штрафы, сумму, балл из 100, `passed`, результат сопоставления и его причину.

Старые результаты сохраняют прежнюю оценку и отчёт; интерфейс помечает оценку как старую, без пересчёта в новую шкалу. Удаление задания не удаляет условие и решение из сохранённой попытки. Контроллеры хранилища принимают `StoragePort` для изолированной проверки. Тема хранится в `automata.theme`.

## Запуск и проверка

```bash
npm ci
npm run dev
npm test
npm run lint
npm run build
npm run electron
```

Тесты компилируют реальные контроллеры и компоненты и запускаются стандартным `node:test`. Проверяются ввод алфавитов и ссылки, точная длительность заморозки, очистка и отмена таймера, независимость сопоставления от баллов, штрафы и порог 50, сохранение снимков и совместимость, формы, стек, переходы, Unicode, фильтры, сессия и тема.

## Сборка установщика Windows (.exe)

В Windows установите Node.js 22 LTS с npm, откройте PowerShell или CMD в папке проекта и выполните:

```powershell
npm ci
npm run electron:pack:win
```

Команда проверит тесты, соберёт интерфейс и создаст установщик для Windows x64: `release/Automata-Setup-0.0.0.exe` (версия берётся из `package.json`). Автоматической публикации нет. Установщик позволяет выбрать каталог установки и создаёт ярлыки. При первой сборке нужен интернет для загрузки зависимостей, Electron и инструментов NSIS; установленное приложение работает локально. Получателю достаточно передать установщик — Node.js и исходники ему не нужны.

`npm ci` только устанавливает зависимости. Сборка `.exe` запускается отдельной командой `npm run electron:pack:win`. Обычная сборка для текущей ОС остаётся доступна через `npm run electron:pack`. Для сборки Windows используйте Windows; сборка с Linux требует отдельно настроенных средств кросс-сборки.

## Как передать текущее задание вместе с .exe

Задание, созданное преподавателем, сохраняет название и описание в локальном хранилище текущего профиля и остаётся после перезапуска. Сборка исходников сама не читает это хранилище: задание из браузерной версии или другой установки не попадёт в установщик автоматически.

В текущие исходники уже включено задание **«Адрес»**: «Название улицы 5-10 букв, первая буква улицы обязательно заглавная. У дома длина 1-3 цифры, а у квартиры 1-2 цифры.» Оно хранится в `src/data/default-tasks.json`, поэтому для передачи этого условия достаточно обычной сборки `npm run electron:pack:win`. В новом профиле после регистрации ученика задание появится в разделе «Доступные задания»; кнопка «Выполнить» открывает его описание и форму решения. Чтобы заменить этот набор другими заданиями, используйте экспорт:

1. В той версии приложения, где создано задание, войдите как преподаватель и на вкладке заданий нажмите **«Экспорт заданий»**. Сохранится файл `default-tasks.json` со всеми текущими заданиями. Если нужно передать только одно, оставьте в массиве JSON только его объект; удалять остальные задания в приложении не требуется.
2. На компьютере, где будете собирать установщик, включите экспорт в исходники:

   ```powershell
   npm ci
   npm run tasks:bundle -- "C:\Users\YourName\Downloads\default-tasks.json"
   npm run electron:pack:win
   ```

   Укажите фактический путь к скачанному файлу. Команда проверяет названия, описания и уникальность идентификаторов, затем заменяет `src/data/default-tasks.json`. Альтернатива — вручную скопировать экспорт в этот файл до сборки. Если кнопки нет в ранее запущенной версии, обновите или перезапустите её с актуальными исходниками в том же профиле.
3. Передайте `release/Automata-Setup-0.0.0.exe`. При первом открытии списка заданий в новом профиле приложение автоматически сохранит включённые задания с их описаниями. Преподавателю не нужно создавать их повторно.

Файл `src/data/default-tasks.json` также можно заполнить вручную. Текущий набор:

```json
[
  {
    "id": "assignment-address",
    "title": "Адрес",
    "description": "Название улицы 5-10 букв, первая буква улицы обязательно заглавная. У дома длина 1-3 цифры, а у квартиры 1-2 цифры."
  }
]
```

У пользователя с уже существующим ключом `tasks` новая сборка не добавляет и не заменяет задания. Удалённые задания не появляются заново после перезапуска. Чтобы распространить другой набор новым пользователям, повторите экспорт и сборку. Результаты учеников, данные входа, тема и штрафы в экспорт не входят.

Данные приложения хранятся отдельно от установщика в профиле Windows. Настройка `deleteAppDataOnUninstall: false` сохраняет их при обычном удалении приложения; удаление профиля или очистка хранилища удалит локальные данные. Хранилище версии `npm run dev` отдельно от установленного `.exe`. Резервную копию заданий можно сохранить кнопкой экспорта.
